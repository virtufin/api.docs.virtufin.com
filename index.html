    Virtufin API

    A gRPC-based API gateway server with support for service invocation, event streaming, Dapr integration, and service discovery.

    Overview

    Virtufin API provides a unified gateway for managing and invoking backend services with:

    • gRPC and gRPC-Web support for service invocation and event streaming
    • Dapr integration for pub/sub messaging and state management
    • Service discovery via gRPC reflection (mandatory for all backend services)

    Backend services MUST implement gRPC reflection. The API Gateway uses reflection for method discovery, schema validation, and dynamic gRPC invocation. Services without it cannot be proxied through the gateway. - REST API for HTTP clients and OpenAPI documentation

    Key Components

    Component Description
    GatewayService gRPC service for method invocation and event subscriptions
    GrpcReflectionService Dynamic service discovery via gRPC reflection
    GrpcChannelPool Thread-safe pooling of gRPC channels per service
    EventSubscriptionManager Manages event subscriptions and broadcasting
    DaprStreamingSubscriptionManager Dapr pub/sub streaming integration

    Quick Start

    Prerequisites

    • .NET 10+ SDK
    • Dapr CLI
    • A configured services.yaml

    Running Locally

    # Start Dapr sidecar
dapr init

# Run the API
cd src/Virtufin.Api
dotnet run

# API available at:
# - HTTP (REST, Swagger, gRPC-Web): http://localhost:5001
# - gRPC (native gRPC h2c):         http://localhost:5002
# - Swagger UI: http://localhost:5001/swagger

    Using the C# Client

    using Virtufin.Api.Client;

// Create client
using var client = new ApiClient("localhost", 5002);

// List available services
var services = await client.ListServicesAsync();
Console.WriteLine($"Services: {string.Join(", ", services.Services)}");

// Get service client and invoke a method
var serviceClient = client.Gateway.GetService("workmanager");
var result = await serviceClient.InvokeAsync("GetStatus");

// Or invoke directly
var response = await client.InvokeAsync("workmanager", "GetStatus",
    new Dictionary<string, object?> { ["key"] = "value" });

    Documentation Building

    This documentation is built using MkDocs and published automatically via CI on the master branch.

    Local Preview

    # Preview documentation
python scripts/generate_docs.py --serve

    Building

    The documentation is automatically built and deployed by CI. To build locally:

    # Build documentation site to docs-site/
python scripts/generate_docs.py

# Generate API reference docs (C#, Python, TypeScript)
python scripts/generate_docs.py --api-docs

    CI/CD

    Documentation is automatically built and deployed when changes are pushed to master. The workflow:

    1. CI builds MkDocs site (mkdocs build)
    2. CI injects the Git commit SHA into mkdocs_v1.yml
    3. CI generates API reference docs (DocFX, pdoc, TypeDoc)
    4. CI deploys to GitHub Pages

    No manual deployment is required.

    Port Configuration

    Port Protocol Purpose
    5001 HTTP/gRPC-Web HTTP port (REST, Swagger, health, gRPC-Web)
    5002 gRPC (h2c) Native gRPC HTTP/2 port
    3500 HTTP Dapr HTTP (default)
    50001 gRPC Dapr gRPC (default)
